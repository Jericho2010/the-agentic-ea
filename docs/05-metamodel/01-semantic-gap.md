# 6.1 — The semantic gap without a metamodel

Across S01–S20, teams emit “applications,” “systems,” “repos,” “components,” and “services” that may or may not be the same entity.

Without a shared metamodel:

- S01 billing tags ≠ S05 ADR headers ≠ S09 OpenAPI titles ≠ S15 CycloneDX components
- Agents hallucinate joins
- Lakehouse tables become parallel spreadsheets
- Archify diagrams invent nodes that cannot be audited

Orbus Infinity’s CoreEA solved this **inside a proprietary store**. PAM solves it **in Git + lakehouse** with open semantics. [@orbus-coreea] [@wcid-agy-research]

## The multi-hop question that justifies PAM

> If we sunset Oracle DB (technology), which business capabilities and customer journeys fail, who owns them, what do they cost, and which CVEs are open?
